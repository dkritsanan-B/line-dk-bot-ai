# งานวิจัยคู่แข่ง + ช่องว่างระบบสมาชิก DK

เอกสารนี้สรุปผลวิจัยรอบที่ 1 (16 ก.ย. 2569) ของงาน `member-polish` — ประกอบด้วย (ก) โปรแกรมสมาชิกของร้านวัสดุ 5 เจ้า (ข) งานวิจัยว่าช่าง/ผู้รับเหมาสนใจอะไรจริง (ค) บทเรียน UX ของ LINE OA/LIFF (ง) ผลตรวจโค้ดระบบเราเอง แล้วแปลงเป็นช่องว่างรายชิ้น P0–P8 ตามบรีฟ `docs/BRIEF-member-polish-ultracode.md`

**กติกาของเอกสารนี้:** ทุกบรรทัดมาจากผลวิจัยรอบที่ 1 เท่านั้น ไม่มีการเติมข้อมูลจากความจำ — ตรงไหนที่ผู้วิจัยบอกว่าหาไม่พบ เขียนว่า "ไม่พบข้อมูล" ตรงไหนที่แหล่งขัดกัน เขียนไว้ว่าขัดกันตรงไหน

**ข้อจำกัดที่ต้องรู้ก่อนอ่าน**

- ผลตรวจโค้ดครบ 3 ส่วน: `liff-main` (หน้า /liff), `liff-rewards` (หน้า /liff/rewards + flow แลกของ), `api-data` (lib/points, lib/tierRules, lib/liff-auth, API สมาชิกทั้งชุด)
- **ผลตรวจ `line-messages` และ `admin` ไม่มีในผลวิจัยรอบนี้** — agent 2 ตัวนี้ถูกขัดจังหวะก่อนสรุปผล (ตรวจ journal แล้วมีแต่บรรทัด "จะเริ่มสำรวจไฟล์" ไม่มีผลลัพธ์) ดังนั้น **ช่องว่างของ P7 และ P8 ในเอกสารนี้อ้างได้เฉพาะส่วนที่ audit อื่นบังเอิญเดินผ่าน** (เช่น `api-data` ที่ไล่ push message ทุกตัว และ `liff-rewards` ที่ไล่ flow ถึง `/api/admin/redemptions`) — ไม่ใช่การตรวจเต็ม ต้องตรวจซ้ำก่อนลงมือ P7/P8
- เว็บสาธารณะของคู่แข่ง ≠ หน้าจอในแอปของเขาหลังล็อกอิน ใช้เทียบได้เฉพาะ "การเล่าสิทธิ์ / ชวนสมัคร / ตารางระดับ" ตามที่บรีฟกำหนด

### 3.2 เรื่อง broadcast / โควตา

- แหล่งไทยหลายเจ้า (cresclab / iship / sniper) ตรงกันว่า **ส่งบ่อย/ไม่ตรงใจ = block rate พุ่ง** ความถี่ที่เหมาะสมคือ **2-3 ครั้ง/สัปดาห์** และควรเปลี่ยนเป็นข้อความ trigger-based รายคน
- SMARTKORP แนะนำ push เฉพาะเหตุการณ์: แต้มใกล้หมดอายุ / เลื่อนระดับ / แต้มพอแลกแล้ว / วันเกิด · LINE Help มีตัวอย่าง "คุณมีแต้มอีก 200 แต้มที่จะหมดอายุใน 14 วัน"
- **DK มีข้อจำกัดแรงกว่าคนอื่น**: โควตาฟรี 300 ข้อความ/เดือน และเคยหมดไปกับ push สรุปงานหา staff มาแล้ว → **ห้าม push "แต้มเข้าแล้ว" ทุกบิล** (ร้านวัสดุออกบิลวันละหลายสิบใบ = หมดใน ~1 สัปดาห์) ให้แต้มขึ้นเงียบๆ บนบัตร แล้ว push เฉพาะ "แต้มพอแลกแล้ว" กับ "แต้มใกล้หมดอายุ" · ถ้าลูกค้าทักมาก่อนให้ใช้ reply (ฟรี)

## 5. คำถามที่ต้องให้เจ้าของร้านตัดสิน

> ทุกข้อเป็นเรื่องนโยบาย/ธุรกิจ ที่บรีฟข้อ 2 ห้าม agent ตัดสินเอง ("ถ้าคิดว่ากติกาควรเปลี่ยน ให้บันทึกเป็นข้อเสนอ ไม่ลงมือ")

1. **Bronze ได้ 0% — จะให้ "ของทันทีตอนสมัคร" ไหม และเป็นอะไร?**
   งานวิจัยชี้ตรงกัน 3 แหล่ง (trade loyalty ข้อ 7 · LIFF UX · KJL/Do Home) ว่าสมัครแล้วไม่ได้อะไร = ตายใน 30 วันแรก · ทางเลือกที่ผู้วิจัยเสนอและไม่กระทบมาร์จิ้นเหล็ก: คูปองลด 50-100 บาทเฉพาะหมวดปลีก / ถุงมือหรือตลับเมตรใบแรก / ให้แต้มตั้งต้น 100 แต้ม (= Bronze ทันที) · **ต้องเลือกอย่างใดอย่างหนึ่งหรือไม่ให้เลย**

2. **จะดึงลูกค้าเครดิต/วางบิลที่มีอยู่แล้วเข้าระบบอัตโนมัติหรือไม่?**
   Toolstation ให้เข้า Trade Club อัตโนมัติถ้ามีบัญชีเครดิตอยู่แล้ว ไม่ต้องสมัคร · DK มีรายชื่อ CSCUSTOMER อยู่แล้ว แต่การ auto-link จากเบอร์ถูกกันไว้ในโค้ดโดยเจตนา (กันสวมสิทธิ์) → ถ้าจะทำต้องเป็น "แอดมินกดอนุมัติเป็นชุด" ไม่ใช่ auto

3. **กติกาแต้มแยก 5 หมวดจะเก็บไว้ หรือย่อให้เล่าจบใน 1 ประโยค?**
   **ผลวิจัยขัดกันตรงนี้และต้องให้เจ้าของตัดสิน** — ฝั่ง LIFF UX (SMARTKORP 10-second test) แนะนำให้ "ล็อกสูตรเดียวทั้งร้าน อย่าทำอัตราแยกตามหมวดในเฟสแรก" แต่ฝั่ง trade loyalty ชี้ว่า **การให้สิทธิ์กับเหล็ก/ปูนคือจุดที่ DK แซงคู่แข่งทั้ง 3 เจ้าได้ชัดที่สุด** (ไทวัสดุ HomePro Do Home ตัดเหล็ก-ปูนออกหมด) ซึ่งต้องแยกหมวดถึงจะทำได้ · ทางประนีประนอมที่ผู้วิจัยเสนอ: เก็บเมทริกซ์ไว้ในระบบ แต่บนจอโชว์เฉพาะ **แถวของระดับตัวเอง 5 บรรทัด** และเขียนผลลัพธ์เป็น **บาท ไม่ใช่ %**

4. **จะเปลี่ยนชื่อระดับจาก Welcome/Bronze/Silver/Gold/Platinum/Diamond เป็นภาษาช่างไหม?**
   ผู้วิจัยเสนอแนวทาง "ลูกค้าประจำ / ช่างประจำร้าน / หัวหน้าช่าง / นายช่างใหญ่" (อ้างอิง KJL: ดาวรุ่ง/ทีโปร/นายช่าง และ Do Home: ครอบครัวช่าง) · **แต่ป้าย A4 พิมพ์ไปแล้ว** ต้องตัดสินว่าคุ้มที่จะพิมพ์ใหม่ไหม

5. **บัตรจะเป็น QR หรือบาร์โค้ด หรือทั้งคู่ — และเครื่องสแกนที่เคาน์เตอร์เป็นแบบไหน?**
   ต้องไปดูของจริงก่อน: สแกนเนอร์เลเซอร์ 1D อ่าน QR จากหน้าจอมือถือไม่ได้เลย · ถ้าเป็นเลเซอร์ ต้องแสดงทั้งบาร์โค้ด 1D (เบอร์/รหัสสมาชิกตัวเลขล้วน) และ QR บนบัตรใบเดียวกัน หรือกลับด้านให้ลูกค้าเป็นคนสแกน QR ของร้าน · **ข้อนี้บล็อกงาน P3 ตรงๆ**

6. **จะให้เคลมบิลย้อนหลังได้ไหม และกี่วัน?**
   Pro Xtra ให้เติมบิลย้อนหลังได้ภายในไตรมาส/12 เดือน · Benjamin Moore 60 วัน · Global House ประกาศเลยว่าไม่ให้สะสมย้อนหลัง (ผู้วิจัยจัดเป็นจุดอ่อน) · ผู้วิจัยเสนอ 7-30 วัน + admin กดอนุมัติ ผ่าน `/api/admin/add-points` ที่มีอยู่แล้ว

7. **จะให้ช่าง 1 คนผูกรหัสลูกค้า Hero ได้มากกว่า 1 รหัสไหม?**
   ตอนนี้เป็น 1:1 → แต้มรั่วทุกครั้งที่ออกบิลในนามเจ้าของบ้าน · และถ้าจะให้แต้มจากบิลที่เจ้าของบ้านจ่าย **ต้องเขียนกติกาเปิดเผยไว้ในหน้าเงื่อนไข** (หลักจริยธรรมจัดซื้อ: ไม่เปิดเผย = kickback)

8. **โควตา LINE — จะยอมจ่ายเพิ่มไหม หรือยึดหลัก "push เฉพาะ 2 กรณี"?**
   ถ้ายึดของฟรี 300 ข้อความ/เดือน ต้องตัด push "แต้มเข้าแล้ว" ทุกบิลทิ้ง และเหลือเฉพาะ "แต้มพอแลกแล้ว" + "แต้มใกล้หมดอายุ" (บวกเลื่อนระดับ/วันเกิดซึ่งมีอยู่แล้ว) · **ข้อนี้กำหนดขอบเขต P7 ทั้งชิ้น**

9. **แต้มหมดอายุ 1 ปี จะเก็บไว้ไหม?**
   คู่แข่งทุกเจ้าใช้ 2 ปี (HomePro/ไทวัสดุ/Do Home) หรือขัดกันเอง (SCG 1 vs 2 ปี · Global House นับจากวันไหนไม่ชัด) · ของเรา 1 ปี สั้นที่สุดในกลุ่ม และงานวิจัยเตือนว่าแต้มหมดอายุแบบเงียบ = เรื่องผิดใจมากกว่าแรงจูงใจ

10. **ของรางวัลในแคตตาล็อกจะเป็นอะไร และจะมี "ของชิ้นเล็กที่แจกลูกน้องได้" ไหม?**
    งานวิจัยชี้ชัด: เครื่องมือ 60% และ 50% ของช่างจะแบ่งรางวัลให้ลูกน้อง · ผู้วิจัยเสนอ ตลับเมตร ระดับน้ำ ใบตัด ถุงมือ หมวก เสื้อทีม ลูกหมู สว่าน แบตสำรอง — โดยให้ของแจกลูกน้อง (ถุงมือ/เสื้อ) อยู่ชั้นแต้มต่ำ

11. **จะทำ "สิทธิ์ที่ไม่ใช่ส่วนลด" ไหม?**
    งานวิจัยชี้ว่านี่คือสนามที่ร้านท้องถิ่นชนะเชนใหญ่ได้จริง เพราะคู่แข่งทั้ง 5 เจ้าถูกจัดเป็นจุดอ่อนข้อเดียวกันหมด: ไม่มีเครดิตเทอม ไม่มีคิวตัดเหล็ก ไม่มีส่งด่วนถึงหน้างาน ไม่มีจองของล่วงหน้า ไม่มีสายตรงถึงคนขาย · **แต่ทั้งหมดนี้เป็นภาระหน้าร้านจริง ต้องเจ้าของตัดสินว่าทำไหวข้อไหน**

12. **จะให้ P7 และ P8 ตรวจซ้ำก่อนลงมือไหม?**
    ผลตรวจ `line-messages` และ `admin` ไม่มีในรอบนี้ — ถ้าเริ่ม P7/P8 โดยไม่ตรวจซ้ำ จะเป็นการเดาว่าโค้ดปัจจุบันเป็นอย่างไร
