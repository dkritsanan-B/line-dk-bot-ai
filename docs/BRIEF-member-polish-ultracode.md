## 2. คู่เทียบและวิธี blind test

- คู่เทียบ: **ไทวัสดุ (VIZ Card), HomePro (HomeCard), Global House, Do Home, SCG Home** ไม่ใช่ Starbucks/Sephora เพราะลูกค้าเราไม่ได้ใช้และไม่ได้คาดหวังแบบนั้น
- **ภาพคู่เทียบ = แคปเองจากเว็บสมาชิกสาธารณะของแต่ละแบรนด์ด้วย Playwright** (มือถือ 390×844) เก็บที่ `docs/benchmarks/<แบรนด์>/<หน้า>.png` พร้อม `source.json` ที่ระบุ URL + วันที่แคป · ข้อจำกัดที่ต้องเขียนกำกับ: หน้าเว็บสาธารณะไม่เท่ากับหน้าในแอปของเขา ใช้เทียบได้เฉพาะ "การเล่าสิทธิ์/ชวนสมัคร/ตารางระดับ" ไม่ใช่หน้าแดชบอร์ดหลังล็อกอิน · หน้าหลังล็อกอินให้เทียบจากงานวิจัยข้อความแทน และผู้ตรวจต้องระบุว่าเป็นการเทียบแบบอ้อม
- blind test: ผู้ตัดสิน 3 ตัว context ใหม่ ได้รับภาพ 2 ภาพชื่อไฟล์สุ่ม (ของเรา vs คู่เทียบ หน้าเดียวกัน) โดยไม่บอกว่าอันไหนของใคร ตอบว่า "ภาพไหนทำให้อยากสมัคร/เข้าใจสิทธิ์เร็วกว่า เพราะอะไร" ของเราต้องชนะ ≥ 2 ใน 3

## 4. ผู้ตรวจ (ทุกคน context ใหม่ ห้ามอ่านสรุปของคนสร้าง)

ทุกชิ้นถูกตรวจจาก **ภาพหน้าจอที่เรนเดอร์จริงด้วย Playwright** ที่ 2 ขนาด: มือถือ 390×844 (จำลอง Android + throttle 4G) และเดสก์ท็อป 1280×800 และผู้ตรวจต้อง **กดใช้จริง** (กรอก กด เลื่อน) ไม่ใช่ดูแค่ภาพนิ่ง

1. **นักออกแบบโหด** ให้คะแนน 1-10 ใน 6 ด้าน: ลำดับสายตา, ตัวอักษร, ระยะห่าง, สี/contrast, ความสม่ำเสมอกับหน้าอื่น, ความง่าย และต้องระบุ **ช่องว่างใหญ่สุดข้อเดียว** พร้อมพิกัดบนภาพ
2. **ลูกค้าจริง** (สุ่ม persona A หรือ B ตามชิ้น) ตอบ 3 คำถาม ใช่/ไม่ใช่ พร้อมเหตุผล: "ฉันเข้าใจว่าได้อะไร" "ฉันจะสมัคร/ใช้ต่อ" "ฉันอยากกลับมาดูอีก" และถามเพิ่ม "ข้อความไหนทำให้ลังเล"
3. **blind test** (ตามข้อ 2) เฉพาะชิ้น P1 P3 P4 P6
4. **agent เดินทาง journey** สร้างใหม่ทุกรอบใหญ่ 1 ตัว ไม่รู้จัก DK มาก่อน เดินตั้งแต่สแกน QR → สมัคร → รอผูก → แต้มเข้าบิลแรก → เลื่อน Bronze → วันเกิด → แลกรางวัล → เห็นข้อความ LINE → กลับมาดูแต้ม แล้วรายงาน "จุดที่โทนภาพ/น้ำเสียง/ความรู้สึกไม่ต่อกัน" เป็นรายการเรียงตามความรุนแรง

**ชิ้นผ่านเมื่อ:** นักออกแบบ ≥ 8 ทุกด้าน + ลูกค้าตอบ "ใช่" ทั้ง 3 ข้อ **สองรอบติดกัน** + blind test ชนะ (ถ้ามี)
**ทั้งงานเสร็จเมื่อ:** ทุกชิ้นผ่าน + journey agent ไม่พบปัญหาระดับ "ทำให้เลิกสมัคร/เลิกใช้" + build และ typecheck ผ่าน + test ตัวเลขสิทธิ์ผ่าน

## 6. เทคนิคที่ต้องเตรียมก่อนเริ่มรอบแรก (agent ตัวแรกทำ)

1. `git checkout -b member-polish` จาก main
2. `vercel env pull .env.local` เพื่อให้ dev server ในเครื่องมี env ครบ (ตอนนี้ขาด LINE_CHANNEL_SECRET, LINE_LOGIN_CHANNEL_ID, NEXT_PUBLIC_LIFF_ID, CRON_SECRET, DATABASE_URL, SHEET_CSV_URL, LINE_STAFF_GROUP_ID) แล้ว `npm run dev` ที่พอร์ตว่าง (ระวังพอร์ตที่ Windows จองไว้ ดูด้วย `netsh interface ipv4 show excludedportrange protocol=tcp`)
3. **โหมดรีวิว** (ไม่มีอยู่ ต้องสร้าง): LIFF จริงต้องล็อกอิน LINE ในแอปเท่านั้น Playwright เปิดไม่ได้ ให้เพิ่ม `REVIEW_SECRET` (เฉพาะ `VERCEL_ENV !== "production"` หรือ dev) และ query `?review=<secret>&as=<scenario>` ที่ server ตอบข้อมูลสมาชิกจำลอง 6 สถานการณ์: `new` (ยังไม่สมัคร), `pending` (รอผูกรหัส), `bronze120`, `gold2300_expiring`, `birthday`, `diamond` ห้ามให้โหมดนี้เข้าถึงข้อมูลลูกค้าจริง และต้องมี test ยืนยันว่าบน production เปิดไม่ได้
4. ติดตั้ง Playwright เฉพาะโปรเจกต์นี้ `npm i -D playwright` (เบราว์เซอร์ Chromium มีอยู่แล้วที่ `%LOCALAPPDATA%\ms-playwright`) + สคริปต์ `scripts/review-shots.mjs` ที่ถ่ายทุกหน้า × ทุก scenario × 2 ขนาด ลง `review/<รอบ>/<ชิ้น>/*.png` เพื่อให้ผู้ตรวจดูภาพชุดเดียวกัน
5. หน้า progress: `progress/index.html` ในโปรเจกต์ (meta refresh ทุก 30 วิ) เปิดใน Chrome ค้างไว้ ตัวควบคุมอัปเดตทุกครั้งที่ชิ้นเปลี่ยนสถานะ: ตาราง ชิ้น × รอบ × คะแนน × ช่องว่างล่าสุด × ภาพล่าสุด (thumbnail) + โทเคนที่ใช้ไป
6. LINE: ทดสอบ Flex ด้วย validate endpoint ก่อนเสมอ ส่ง push จริงได้เฉพาะ LINE ของเจ้าของร้าน รวมไม่เกิน 20 ข้อความทั้งโปรเจกต์ (โควตา 300/เดือน มีใช้จริง)
