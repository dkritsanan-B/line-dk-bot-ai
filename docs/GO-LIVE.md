# ขึ้นระบบจริง: branch member-polish

เขียน 16 ก.ย. 2569 · สถานะ: **ยังไม่ขึ้นระบบจริง** โค้ดอยู่บน branch `member-polish` เท่านั้น

## ทำไมยังไม่ขึ้นทันที

งานรอบนี้แก้เรื่องเงินของลูกค้า 3 จุด ได้แก่ ตัวตัดแต้มหมดอายุรายคืน การยืนยันแลกของ และการให้/หักแต้ม
ทุกจุดพิสูจน์กับ Postgres ที่รันในเครื่องแล้ว แต่ยังไม่เคยรันกับฐานข้อมูลจริงของร้าน (Neon)
ตัวตัดแต้มรันเองทุกคืนเวลา 01:00 น. ถ้าขึ้นระบบแล้วมีอะไรผิด แต้มลูกค้าจริงจะถูกตัดก่อนมีใครเห็น
จึงต้องมีขั้นตรวจแบบ "คำนวณแต่ไม่เขียน" กับข้อมูลจริงก่อนหนึ่งรอบ

## ก่อนขึ้นระบบ (ทำบนเครื่องนี้)

```
npm test
```

ทุกคำสั่งต้องผ่าน

## ขั้นตอนขึ้นระบบ

1. push branch แล้ว merge เข้า main (Vercel ทีม dk-boss-projects จะ deploy ให้เอง)
2. **ภายในวันเดียวกัน ก่อน 01:00 น.** เรียกตัวตัดแต้มแบบไม่เขียน (dry run) กับข้อมูลจริง แล้วดูตัวเลข
   ```bash
   curl -H "Authorization: Bearer $CRON_SECRET" "https://<โดเมนจริง>/api/cron/expire-points?dry=1"
   ```
   - จำนวนสมาชิกที่จะถูกตัด และแต้มรวมที่จะตัด ต้องสมเหตุสมผล (ร้านเพิ่งเริ่มระบบ ควรเป็น 0 หรือใกล้ 0)
   - ถ้าตัวเลขผิดปกติ ให้ปิด cron `expire-points` ใน vercel.json ก่อน แล้วค่อยหาสาเหตุ
3. ทดสอบด้วยบัญชี LINE ของเจ้าของร้านเอง (ใช้โควตา push น้อยที่สุด)
   - เปิดบัตรสมาชิกในแอป LINE เห็นตัวเลขตรงกับหน้าแอดมิน
   - ถ้ายังไม่ผูกรหัส ต้องขึ้นจอ "รอพนักงานยืนยันตัวตน" · ผูกในหน้าแอดมินแล้วเปิดใหม่ จอนี้ต้องหาย
   - แลกของรางวัลชิ้นถูกสุด 1 ครั้ง → หน้าของรางวัลเห็นแต้มที่จองไว้และเลข #REQ → ยืนยันในแอดมิน → แต้มลดครั้งเดียว มีประวัติ 1 รายการ
   - กดยืนยันซ้ำในแอดมิน ต้องขึ้นว่าดำเนินการไปแล้ว แต้มไม่ลดอีก
4. เช็คโควตา LINE หลังทดสอบ (ควรใช้ไปไม่เกิน 5 ข้อความ)

## งานถัดไปที่ยังไม่ทำ

1. ตัวตัดแต้มแบบ dry run (ต้องมีก่อนขึ้นระบบ)
2. ให้แต้มย้อนหลังตามที่ตัดสินข้างบน (แก้บอทร้าน + เซิร์ฟเวอร์)
3. ข้อความบนหน้าเว็บ: 1 แต้ม = 1 บาท และสิทธิ์ของ Bronze
4. เทียบกับหน้าเว็บคู่แข่งแบบปิดชื่อ (ภาพอยู่ใน docs/benchmarks)
