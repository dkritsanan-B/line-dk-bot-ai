ตัวสร้างกลาง `memberNoticeFlex` รองรับ tone `info`, `warn`, `neutral`, `birthday`, `success` (รับของแล้ว) หรือหัวสีกำหนดเอง, metric หลัก (แบบตั๋วสำหรับหมายเลขคำขอ เว้นตัวอักษรด้วย U+200A / แบบขีดฆ่า / `label` ป้ายเหนือตัวเลข / `chip` ป้ายสถานะข้างตัวเลข เช่น “อีก 30 วัน” / `follow` บรรทัดตัวหนาใต้คำอธิบาย เช่น “ยังใช้ได้ 2,150 แต้ม”), `lead` แทน metric, กล่องข้อมูลสูงสุด 3 แถว (ต่อหลอดความคืบหน้าในกล่องได้), note และปุ่มสูงสุด 2 ปุ่ม กติกาเนื้อหา: eyebrow = `DK MEMBER · หมวด`, หัวข้อ = เหตุการณ์ บรรทัดเดียว (เกิน 16 ตัวย่อเป็น lg, ห้ามมีตัวเลข/เลขคำขอ), caption = ความหมายของตัวเลข, message = ขั้นต่อไป และห้ามมีบรรทัดซ้ำกันในการ์ดเดียว ข้อมูลที่เพิ่มใหม่เป็น optional ทั้งหมด จุดเรียกเดิมจึงใช้พารามิเตอร์ชุดเดิมได้ หากไม่มีข้อมูลเสริม การ์ดจะตัดส่วนนั้นออกหรือใช้คำอธิบายทั่วไปโดยไม่สร้างวันที่ขึ้นเอง

สีร่วมคือ success `#12805C`, warn `#B45309`, warn background `#FFF4E0`, panel `#F4F6FA` และข้อความรอง `#5A6679` ปุ่มหลักใช้สีน้ำเงินแบรนด์และ `height: md` ส่วนปุ่มรองใช้ `secondary` การ์ดแจ้งเตือนไม่มี hero แต่ตัวสร้างกลางรองรับ URL รูปแบบ optional สำหรับอนาคต

สีระดับรวมอยู่ที่ `TIER_THEME` (พื้นหัว, ตัวอักษร, ink, tint, สีหลอด) Gold ใช้ `#F9A825` สีเดียวทุกการ์ด ไม่ใช้เหลือง `BRAND.yellow` บนการ์ดอีก หัว Silver ใช้เงินสว่าง `#CFD8DC` (`#B0BEC5` เดิมดูเป็นการ์ดปิดใช้งาน) และระดับสีสว่าง (Gold/Silver) ใช้หลอดสีน้ำเงินเข้ม ตัวตรวจคำนวณคอนทราสต์ทุกคู่ตัวอักษร/พื้นที่ใช้ (ต้อง ≥ 4.5:1; ต่ำสุดตอนนี้คือ eyebrow โทน warn 4.61)

หลอดความคืบหน้า (`pointsFlex`, `pointsEarnedFlex`) เติม = `totalEarned / next.min` กติกาเดียวกับหน้าบัตร LIFF จึงตรงกับป้าย “สะสมเลื่อนระดับ X / Y” (บอกชัดว่าเป็นแต้มสะสมตลอดอายุ ไม่ใช่แต้มที่ใช้ได้) ข้อความนำใช้รูปเดียวกันคือ “อีก X แต้ม → ระดับ” ถ้าระดับพักอยู่ (`inactiveRealTier`) จะไม่แสดงหลอด แต่แสดงกล่องเตือนสีส้มแทน ตัวเลขใหญ่บนบัตรยังเป็นแต้มคงเหลือที่ใช้แลกได้

การ์ดใกล้ลดระดับยึด `getEffectiveTier` ใน `lib/points.ts`: ไม่มีบิลภายใน 365 วันนับจากซื้อล่าสุด ระดับจะคิดจากแต้มคงเหลือแทนแต้มสะสม การ์ดบอกชื่อระดับที่จะตกเฉพาะเมื่อผู้เรียกส่ง `tierName` และ `points` มา (คำนวณด้วย `TIER_MIN` ซึ่งตัวตรวจเทียบกับ `TIERS`) ถ้าไม่มีข้อมูลจะบอกเพียงว่า “ถ้าไม่มีบิลใหม่ ระดับอาจลดลง” cron `notify-expiry` ส่งครบแล้ว: `tierName`, `points`, `deadline` = ซื้อล่าสุด + 365 วัน และ `lastPurchaseDate` จึงมีวันที่เป็นตัวเลขหลักเสมอ eyebrow บอกระดับ “DK MEMBER · ระดับ X”

`contactFlex` เป็น carousel 5 ใบ: ใบร้าน (แบนเนอร์ + เวลาทำการ + แถวโทรร้าน + ปุ่มโทรร้าน/แผนที่ร้านซ้อนเต็มความกว้าง) ตามด้วยการ์ดพนักงาน 4 ใบ (รูปมุมมน ชื่อ ป้าย “พนักงานขาย” และปุ่ม 📞 โทร / 💬 เพิ่มเพื่อน LINE ซ้อนเต็มความกว้าง) ขอบล่างทุกใบจึงตรงกันตอนปัด ไม่มีแถว LINE ร้าน (ลูกค้าคุยในบัญชีนี้อยู่แล้ว) และไม่ใส่ที่อยู่/ย่านเพราะไม่มีใน `SHOP` ไม่เขียนความถนัดของพนักงานขึ้นเอง (ตัวตรวจบังคับ) `welcomeFlex` มีปุ่มหลัก “สมัครสมาชิกฟรี” และปุ่มรองคู่กันแถวเดียว

สิทธิ์บนการ์ดเลื่อนระดับอ้างอิงค่าจาก `lib/tierRules.ts`; แต้มวันเกิดอ้างอิงตารางใน `app/api/cron/birthday/route.ts` คือ Bronze 100, Silver 200, Gold 500, Platinum 800 และ Diamond 1,000 แต้ม ตัวเลขเหล่านี้คัดลอกไว้ใน `MEMBER_BENEFITS` ของ `lib/line-ui.ts` (import ไฟล์ต้นทางตรงไม่ได้เพราะต่อฐานข้อมูล) และ `scripts/validate-line-messages.mjs` อ่านไฟล์ต้นทางมาเทียบทุกครั้ง ถ้าแก้กติกาแล้วลืมแก้การ์ด ตัวตรวจจะล้ม ข้อความต้อนรับคำนวณจากตารางเดียวกัน: ส่วนลดหน้าร้านสินค้าปลีก 1–4% เริ่มที่ระดับ Silver (Welcome/Bronze ยังไม่มีส่วนลด) และแต้มวันเกิดตั้งแต่ระดับ Bronze

`app/api/cron/test/route.ts` เป็นเครื่องมือ super admin ที่จำลอง “แต้มใกล้หมดอายุ” และ “แต้มหมดอายุแล้ว” จึงเรียกตัวสร้าง Flex ชุดเดียวกับ cron จริง ไม่มีข้อความอีกสำเนาหนึ่ง

## การตรวจรูปแบบ

รัน `node --import tsx scripts/validate-line-messages.mjs` เพื่อตรวจตัวอย่างทั้งข้อมูลเดิมและข้อมูล optional ในเครื่อง ตัวตรวจยืนยันโครง Flex, ความยาว `altText`, action ของปุ่ม, จำนวนแถว/ปุ่ม, สีที่เลิกใช้, หัวข้อบรรทัดเดียว, บรรทัดซ้ำ, หลอดตรงกับป้าย, คอนทราสต์สี, สิทธิ์และเกณฑ์ระดับเทียบไฟล์ต้นทาง, กติกาลดระดับ และค่าคงที่เวลาร้าน โดยไม่อ่าน `.env.local`, ไม่เรียก LINE API และไม่ส่งข้อความจริง

ตรวจ TypeScript และชุดทดสอบโครงการด้วย `npx tsc --noEmit` และ `npm test` ตามลำดับ ตัวอย่างภาพสร้างด้วย `render.mjs` ทั้งแบบปกติและ `--extra` และ `render-opt.mjs` ตัวเลขตัวอย่างต้องเป็นไปได้ตามเกณฑ์ 100/500/2,000/5,000/10,000 (เช่น Gold สะสม 3,200 → Platinum 5,000, แต้มคงเหลือไม่เกินแต้มสะสม) ตัวตรวจเช็คทุกป้าย “สะสมเลื่อนระดับ X / Y” ว่า X อยู่ในช่วงระดับก่อน Y

## รอบรีวิว 6 (17 ก.ย. 69)

- ต้อนรับ: ซับไตเติลเป็นเหตุผลที่ควรสมัคร ไอคอนแถวเป็นวงกลมสีแบรนด์ชุดเดียว (★ % ♥ — รอบ 7 เปลี่ยน ♥ เป็น ✦) แทนอีโมจิ
- ติดต่อฝ่ายขาย: การ์ดพนักงานไม่มีหัวซ้ำ ใต้ชื่อเป็นป้าย “พนักงานขาย · 1/4” (ไม่มีเบอร์ซ้ำกับปุ่มโทร) ปุ่มโทรเป็นปุ่มหลัก ปุ่ม “เพิ่มเพื่อน LINE” เป็นปุ่มรองไม่มีอีโมจิ รูปพนักงาน 5:6 ให้สูงเท่าใบร้าน
- เช็คแต้ม: ชื่อผ่าน `who()` เสมอ (ไม่โชว์เบอร์)
- แต้มใกล้หมดอายุ/หมดอายุ: ทักชื่อ, ป้ายวันเหลือ/ป้าย “หมดอายุ”, ยอดเหลือ 0 ใช้หัวข้อ “แต้มหมดอายุแล้ว”
