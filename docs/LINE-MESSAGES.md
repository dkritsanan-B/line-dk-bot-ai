# บัญชีข้อความ LINE

สำรวจจาก endpoint `/v2/bot/message/*` ทั้งหมดในโปรเจกต์ ณ วันที่ 17 กันยายน 2569 ตารางนี้แยกข้อความลูกค้าออกจากข้อความกลุ่มพนักงาน และระบุตัวสร้างที่ใช้งานอยู่

## ข้อความสมาชิกแบบอัตโนมัติ

| ข้อความ | ส่งเมื่อ | ไฟล์ที่ส่ง | ตัวสร้าง / tone | ข้อมูลเสริมที่ส่งได้ |
|---|---|---|---|---|
| ได้แต้มจากบิล | มีตัวสร้างไว้สำหรับข้อมูลบิล แต่ระบบปัจจุบันไม่ push ทุกบิลเพื่อรักษาโควตา | `lib/line-ui.ts` | `pointsEarnedFlex` · info | ระดับ, แต้มสะสม และระดับถัดไป เพื่อแสดงแถบความคืบหน้า |
| เลื่อนระดับ | บิลจาก Hero เพิ่มแต้มจนข้ามระดับ และมี LINE user ID | `app/api/hero/points/route.ts` | `tierUpFlex` · หัวสีของระดับนั้น (`TIER_THEME`) | ไม่มี การ์ดแสดงป้ายระดับใหญ่ + สิทธิ์ตามกติกาสมาชิก |
| ของขวัญวันเกิด | cron ให้แต้มวันเกิดแก่ Bronze ขึ้นไปสำเร็จ และมี LINE user ID; Welcome ไม่ได้แต้มวันเกิด | `app/api/cron/birthday/route.ts` | `birthdayGiftFlex` · birthday (ชมพูอ่อน) | ไม่มี |
| แต้มใกล้หมดอายุ | cron พบก้อนแต้มในช่วงเตือนที่ยังไม่เคยแจ้ง | `app/api/cron/notify-expiry/route.ts` | `pointsExpiringFlex` · warn | แต้มคงเหลือทั้งหมด |
| แต้มหมดอายุแล้ว | cron ตัดแต้มที่ครบ 1 ปีสำเร็จ และมี LINE user ID | `app/api/cron/expire-points/route.ts` | `pointsExpiredFlex` · neutral | ไม่มี (ตัวเลขใหญ่คือแต้มที่หมดอายุ ขีดฆ่า ยอดคงเหลืออยู่ในกล่อง) |
| จองของรางวัล | ระบบบันทึกคำขอและจองแต้ม/สต็อกสำเร็จ | `app/api/liff/redeem/route.ts` | `redemptionRequestedFlex` · info | ไม่มี |
| รับของรางวัล | พนักงานยืนยันคำขอสำเร็จ | `app/api/admin/redemptions/route.ts` | `redemptionConfirmedFlex` · info | `requestId` (แสดงแถวหมายเลขคำขอ) — ควรส่ง `row.id` จาก `app/api/admin/redemptions/route.ts` |
| ยกเลิกคำขอ | พนักงานยกเลิกคำขอสำเร็จ | `app/api/admin/redemptions/route.ts` | `redemptionCancelledFlex` · neutral | เหตุผลการยกเลิก, `balance` (ยอดใช้ได้หลังปลดแต้มที่จอง) |
| ใกล้ลดระดับ | cron พบสมาชิกที่ใกล้ครบ 1 ปีนับจากการซื้อล่าสุดและยังไม่เคยแจ้ง | `app/api/cron/notify-expiry/route.ts` | `tierExpiryWarningFlex` · warn | ชื่อระดับ, วันครบกำหนด, วันที่ซื้อล่าสุด, `points` (แต้มคงเหลือ ใช้คำนวณระดับที่จะตก) |

ตัวสร้างกลาง `memberNoticeFlex` รองรับ tone `info`, `warn`, `neutral`, `birthday` หรือหัวสีกำหนดเอง, metric หลัก (แบบตั๋วสำหรับหมายเลขคำขอ / แบบขีดฆ่า), `lead` แทน metric, กล่องข้อมูลสูงสุด 3 แถว (ต่อหลอดความคืบหน้าในกล่องได้), note และปุ่มสูงสุด 2 ปุ่ม กติกาเนื้อหา: eyebrow = `DK MEMBER · หมวด`, หัวข้อ = เหตุการณ์ บรรทัดเดียว (เกิน 16 ตัวย่อเป็น lg, ห้ามมีตัวเลข/เลขคำขอ), caption = ความหมายของตัวเลข, message = ขั้นต่อไป และห้ามมีบรรทัดซ้ำกันในการ์ดเดียว ข้อมูลที่เพิ่มใหม่เป็น optional ทั้งหมด จุดเรียกเดิมจึงใช้พารามิเตอร์ชุดเดิมได้ หากไม่มีข้อมูลเสริม การ์ดจะตัดส่วนนั้นออกหรือใช้คำอธิบายทั่วไปโดยไม่สร้างวันที่ขึ้นเอง

สีร่วมคือ success `#12805C`, warn `#B45309`, warn background `#FFF4E0`, panel `#F4F6FA` และข้อความรอง `#5A6679` ปุ่มหลักใช้สีน้ำเงินแบรนด์และ `height: md` ส่วนปุ่มรองใช้ `secondary` การ์ดแจ้งเตือนไม่มี hero แต่ตัวสร้างกลางรองรับ URL รูปแบบ optional สำหรับอนาคต

สีระดับรวมอยู่ที่ `TIER_THEME` (พื้นหัว, ตัวอักษร, ink, tint, สีหลอด) Gold ใช้ `#F9A825` สีเดียวทุกการ์ด ไม่ใช้เหลือง `BRAND.yellow` บนการ์ดอีก หัว Silver ใช้เงินอ่อน `#B0BEC5` และระดับสีสว่าง (Gold/Silver) ใช้หลอดสีน้ำเงินเข้ม ตัวตรวจคำนวณคอนทราสต์ทุกคู่ตัวอักษร/พื้นที่ใช้ (ต้อง ≥ 4.5:1; ต่ำสุดตอนนี้คือ eyebrow โทน warn 4.61)

หลอดความคืบหน้า (`pointsFlex`, `pointsEarnedFlex`) เติม = `totalEarned / next.min` กติกาเดียวกับหน้าบัตร LIFF จึงตรงกับป้าย “สะสมแล้ว X / Y แต้ม” ข้อความนำใช้รูปเดียวกันคือ “อีก X แต้ม → ระดับ” ถ้าระดับพักอยู่ (`inactiveRealTier`) จะไม่แสดงหลอด แต่แสดงกล่องเตือนสีส้มแทน ตัวเลขใหญ่บนบัตรยังเป็นแต้มคงเหลือที่ใช้แลกได้

การ์ดใกล้ลดระดับยึด `getEffectiveTier` ใน `lib/points.ts`: ไม่มีบิลภายใน 365 วันนับจากซื้อล่าสุด ระดับจะคิดจากแต้มคงเหลือแทนแต้มสะสม การ์ดบอกชื่อระดับที่จะตกเฉพาะเมื่อผู้เรียกส่ง `tierName` และ `points` มา (คำนวณด้วย `TIER_MIN` ซึ่งตัวตรวจเทียบกับ `TIERS`) ถ้าไม่มีข้อมูลจะบอกเพียงว่า “อาจลดลง” cron ปัจจุบันยังส่งแค่ชื่อ

`contactFlex` เป็น carousel 5 ใบ: ใบร้าน (แบนเนอร์ + เวลาทำการ + โทรร้าน/แผนที่) ตามด้วยการ์ดพนักงาน 4 ใบที่มีหัวน้ำเงินบาง รูป ชื่อ เบอร์ และปุ่มโทร/เพิ่มเพื่อน โดยไม่มีแบนเนอร์หรือบรรทัดเวลาซ้ำ `welcomeFlex` มีปุ่มหลัก “สมัครสมาชิกฟรี” และปุ่มรองคู่กันแถวเดียว

สิทธิ์บนการ์ดเลื่อนระดับอ้างอิงค่าจาก `lib/tierRules.ts`; แต้มวันเกิดอ้างอิงตารางใน `app/api/cron/birthday/route.ts` คือ Bronze 100, Silver 200, Gold 500, Platinum 800 และ Diamond 1,000 แต้ม ตัวเลขเหล่านี้คัดลอกไว้ใน `MEMBER_BENEFITS` ของ `lib/line-ui.ts` (import ไฟล์ต้นทางตรงไม่ได้เพราะต่อฐานข้อมูล) และ `scripts/validate-line-messages.mjs` อ่านไฟล์ต้นทางมาเทียบทุกครั้ง ถ้าแก้กติกาแล้วลืมแก้การ์ด ตัวตรวจจะล้ม ข้อความต้อนรับจึงระบุว่าเป็น “แต้มของขวัญวันเกิด” และส่วนลดสูงสุด 4% ตามระดับ

`app/api/cron/test/route.ts` เป็นเครื่องมือ super admin ที่จำลอง “แต้มใกล้หมดอายุ” และ “แต้มหมดอายุแล้ว” จึงเรียกตัวสร้าง Flex ชุดเดียวกับ cron จริง ไม่มีข้อความอีกสำเนาหนึ่ง

| ชวนสมัครก่อนเช็คแต้ม | พิมพ์คำเกี่ยวกับแต้มแต่ยังไม่เป็นสมาชิก | `app/api/line-webhook/route.ts` | Buttons template |
| ติดต่อฝ่ายขาย | พิมพ์คำเกี่ยวกับติดต่อ โทร เบอร์ หรือฝ่ายขาย | `app/api/line-webhook/route.ts` → `contactFlex` | Flex carousel |

## การตรวจรูปแบบ

รัน `node --import tsx scripts/validate-line-messages.mjs` เพื่อตรวจตัวอย่างทั้งข้อมูลเดิมและข้อมูล optional ในเครื่อง ตัวตรวจยืนยันโครง Flex, ความยาว `altText`, action ของปุ่ม, จำนวนแถว/ปุ่ม, สีที่เลิกใช้, หัวข้อบรรทัดเดียว, บรรทัดซ้ำ, หลอดตรงกับป้าย, คอนทราสต์สี, สิทธิ์และเกณฑ์ระดับเทียบไฟล์ต้นทาง, กติกาลดระดับ และค่าคงที่เวลาร้าน โดยไม่อ่าน `.env.local`, ไม่เรียก LINE API และไม่ส่งข้อความจริง

ตรวจ TypeScript และชุดทดสอบโครงการด้วย `npx tsc --noEmit` และ `npm test` ตามลำดับ ตัวอย่างภาพสร้างด้วย `render.mjs` ทั้งแบบปกติและ `--extra`
